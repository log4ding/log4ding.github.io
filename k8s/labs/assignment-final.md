# 파이널 과제 · FE 서비스 운영 리허설

실행·접속·설정·트래픽·배포·장애 대응을 하나의 프로젝트로 연결합니다.

예상 시간: 240분 권장

## 시작 조건

1. 1~10주차 완료. 로컬 클러스터와 Envoy Gateway 사용 가능. 기본 앱은 제공 파일을 재사용할 수 있습니다. 새 프레임워크 개발·도메인 구매·Argo CD 설치는 요구하지 않습니다.
2. final-study Namespace를 사용하고, 다른 과제 리소스와 이름을 섞지 않습니다. 기본 이미지는 준비되어 있으며 시간은 구현·관찰·설명 기준입니다.

## 요구사항

1. 자신의 YAML로 Namespace, Deployment 2개 이상, 버전별 Service, Gateway, HTTPRoute, ConfigMap을 구성하세요. 처음 보는 사람이 적용할 순서를 README에 적으세요.
2. ConfigMap에서 앱의 표시 버전을 주입하고 빌드 시점 FE 환경 변수와 이번 서버 실행 시점 설정의 차이를 설명하세요.
3. Readiness·Liveness·Startup Probe 및 CPU·메모리 requests/limits를 적용하고, 요청 흐름을 localhost부터 Pod까지 그리세요.
4. 두 버전 요청을 90:10 → 50:50 → 0:100으로 전환해 각 단계의 설정과 응답 증거를 남기세요. 수동 전환이며 자동 분석 기능이 아님을 설명하세요.
5. 한 Deployment에서 Rolling Update를 관찰하고 잘못된 이미지 태그 배포를 만든 뒤 이전 버전으로 복구하세요. replicas=2, maxSurge=1, maxUnavailable=0의 의미를 적으세요.
6. 추가 장애 하나를 선택하세요: Service selector 불일치 또는 HTTPRoute의 잘못된 Service 참조. 증상 → 가설 → 확인 명령 → 원인 → 수정 → 재검증 순서로 보고하세요.
7. 가상 도메인의 DNS 입력 표, 도메인 있는 Ingress 또는 Gateway 설정 예시를 작성하세요. 실제 적용하지 않고 도메인·외부 VIP·내부 ClusterIP·TLS의 역할을 설명합니다.
8. 세 배포 전략의 차이를 그림으로 요약하고 이 앱에서 선택할 전략과 이유를 쓰세요. Argo CD가 이 과정에서 맡는 역할과 맡지 않는 역할을 5문장으로 설명하세요.

## 시간 배분

1. 0~25분 — 구조도와 파일 구성 설계
2. 25~85분 — 기본 배포·Service·Gateway 연결
3. 85~125분 — ConfigMap·Probe·리소스 설정
4. 125~165분 — 세 단계 트래픽 전환 관찰
5. 165~210분 — Rollout 실패 복구 및 추가 장애 진단
6. 210~240분 — 도메인 예시·배포 전략·보고서 정리

## 제출물

1. manifests/: 모든 리소스 YAML, 적용 순서, 정상 최종 상태
2. README.md: 전제 조건, 이미지 준비, 실행·확인·종료 순서
3. REPORT.md: 가중치 관측표, Rollout·Rollback 증거, 장애 보고서
4. architecture.md 또는 이미지: 관리 관계·요청 흐름·세 배포 전략 그림
5. domain-example.md: DNS 표·호스트 설정·인증서 참조 설명, Argo CD 역할 요약

## 평가 기준

1. 재현 가능한 구성 — 25점 — 제출된 순서로 정상 앱과 라우팅 재현
2. 연결·설정 설명 — 20점 — Selector·포트·ConfigMap·Probe·자원 설정 이해
3. 트래픽·배포 — 25점 — 단계별 결과와 Rolling Update·Rollback 증거
4. 장애 대응 — 20점 — 실제 출력에 근거한 원인과 복구 확인
5. 통합 설명 — 10점 — 도메인/VIP·세 전략·Argo CD 역할의 정확성

## 힌트

1. 이전 과제 YAML을 재사용해도 되지만 Namespace·라벨·parentRefs·Service 이름을 함께 점검하세요.
2. ConfigMap env 값이 바뀌어도 이미 실행 중인 컨테이너에는 자동 반영되지 않습니다. 새 Pod 반영과 Git/파일의 최종 상태까지 맞추세요.
3. 가중치 테스트 후 최종 보고서에 현재 정상 운영 대상으로 어느 버전을 선택했는지 명시하세요. 실패한 이미지 참조를 제출 YAML에 남기지 않습니다.
4. Argo CD 설명은 Git 선언 반영 → Kubernetes 컨트롤러의 Rollout으로 연결하면 됩니다. 설치 화면이나 Sync 실행 증거는 필요 없습니다.

## 완료와 정리

1. 완료 기준: 정상 상태 재현, 트래픽 분할·배포 복구·추가 장애의 증거, 설명 자료 제출. 4시간은 권장치이며 발표 시간을 별도로 10분 배정합니다. 공개 배포와 도메인 등록은 평가하지 않습니다.
